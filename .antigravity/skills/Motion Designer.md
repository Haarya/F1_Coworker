# Antigravity Skill: Motion Designer

## Description
The Motion Designer skill is the director of the platform's kinetic experience[cite: 2]. While the *GSAP Motion System* writes the technical execution code, the Motion Designer defines the *what*, *when*, and *why*. This skill is responsible for translating the physical dynamics of Formula 1—acceleration, hard braking, pit-stop precision, and camera fly-bys—into elegant, purposeful UI choreography[cite: 2]. Crucially, it ensures that all motion reinforces the high-stakes telemetry data (e.g., the `Cognitive Load Gauge` and `Divergence Alert Banner`) without causing visual fatigue or distraction.

## Activation Criteria
Activate this skill when:
*   Defining the choreography, timing, and sequence of complex UI reveals (e.g., the staggered entrance of dashboard panels on page load).
*   Designing bespoke easing curves that mimic motorsport physics (e.g., snap-deceleration for a UI alert simulating a car entering a heavy braking zone)[cite: 1, 2].
*   Mapping out the visual narrative for the 3-minute Hackathon Presentation strategy (Minute 1: Baseline, Minute 2: High Stress, Minute 3: Firewall Lock)[cite: 1].
*   Specifying how Three.js 3D cameras should interpolate or transition between track hotspots.
*   Defining the fallback choreography for users who have `prefers-reduced-motion` enabled[cite: 2].

## When NOT to Activate
Do NOT activate this skill when:
*   Writing the actual React `@gsap/react` hooks or JavaScript timeline code (delegate to **GSAP Motion System**)[cite: 2].
*   Defining static CSS transitions for simple hover states or base UI tokens (delegate to **UI/UX Design System**)[cite: 2].
*   Rendering the 3D geometries or managing WebGL performance (delegate to **Three.js & React Three Fiber**)[cite: 2].

## Responsibilities
*   **Motion Storytelling:** Architect the sequential flow of animations to guide the user's eye to the most critical information (e.g., forcing focus on the `Cognitive Firewall Overlay` when activated)[cite: 1].
*   **Easing Definition:** Design and document exact bezier curves or spring physics parameters that convey speed and precision.
*   **Choreography Specification:** Deliver clear, step-by-step motion specs (timing, delays, target properties) to the engineering skills.
*   **Restraint Management:** Enforce the core design principle: "Motion should reinforce information, not distract"[cite: 2]. Prevent over-animation of non-critical elements.
*   **Reduced Motion Strategy:** Design elegant, accessible alternative animations (like simple crossfades) to replace aggressive spatial translations for users sensitive to motion[cite: 2].

## Scope
*   Animation sequencing and timeline blueprinting.
*   Easing curve definitions (e.g., cubic-bezier values).
*   Scroll-driven narrative mapping (defining trigger points for `ScrollTrigger`).
*   State-based transition logic (e.g., `Idle` -> `High Stress` -> `Channel Locked`)[cite: 1].

## Non-goals
*   Writing production GSAP code, React refs, or mounting lifecycles[cite: 2].
*   Managing memory leaks or timeline garbage collection (handled by GSAP Motion System)[cite: 2].
*   Designing the static aesthetic textures or typography (handled by Formula 1 Design Language)[cite: 2].

## Inputs
*   Figma designs or structural layouts from the **UI/UX Design System** and **Component Architect**[cite: 2].
*   The high-stakes 3-minute presentation script and telemetry event triggers[cite: 1].
*   Project design principles mandating Apple-quality polish[cite: 2].

## Outputs
*   Detailed motion specifications (Markdown, JSON, or pseudo-code) dictating durations, eases, and property changes.
*   Easing curve mathematical definitions.
*   Narrative storyboards detailing how the 3D scene and DOM elements synchronize.

## Dependencies
*   **AeroFlow Master Project Context:** Relies entirely on the behavioral intent of the dual AI pipeline (e.g., knowing *why* the Divergence Warning fires dictates *how* it should animate)[cite: 1].

## Related Skills
*   **GSAP Motion System (Downstream Executor):** Consumes the specifications generated by this skill to write the actual animation code[cite: 2].
*   **Formula 1 Design Language (Lateral):** Collaborates to ensure the motion feels cohesive with the visual carbon fiber/telemetry aesthetics[cite: 2].

## Folder Ownership
This skill does not typically own React component folders, but governs specification documentation and motion design tokens within:
*   `/src/styles/eases.ts` or similar design-token files where cubic-bezier curves are exported.
*   `/docs/motion-specs/` (if documenting choreography for other agents).

## Naming Conventions
*   **Easing Curves:** Prefix with `ease-f1-` to indicate domain relevance (e.g., `ease-f1-accel`, `ease-f1-brake`, `ease-f1-pit-stop`).
*   **Choreography Sequences:** Name based on the narrative action (e.g., `Sequence_FirewallLock`, `Sequence_TelemetryReveal`).

## Coding Standards
*   *Not Applicable.* This skill produces specifications, not production code. However, pseudo-code specs must clearly indicate the *target property* (e.g., `y: -50`, `opacity: 0`) and the *timing*.

## Design Standards
*   **The Physics of F1:** Motion should mimic vehicle dynamics. An element entering the screen fast and stopping abruptly mimics heavy braking. An element starting slowly and rocketing off-screen mimics acceleration out of an apex[cite: 2].
*   **Information Hierarchy:** In the pit-wall dashboard, data is king. Background telemetry should update with smooth, linear easing. Critical alerts (like Divergence Detection) should use aggressive, high-tension eases to snap the user's attention[cite: 1, 2].
*   **Snappiness over Sluggishness:** Never use overly long, sluggish durations (e.g., > 1.2s for a UI transition) that make the interface feel slow. Target 0.3s to 0.6s for primary UI reveals.

## Performance Standards
*   **GPU-First Design:** Only specify motion for properties that can be GPU-accelerated (`transform` and `opacity`). Never design a choreography that relies on animating `height`, `width`, or `box-shadow`, as the GSAP Motion System will reject it due to layout thrashing[cite: 2].

## Accessibility Considerations
*   **The "Reduced" Spec:** For every complex choreography designed, this skill MUST provide a secondary specification for `prefers-reduced-motion`.
    *   *Standard:* Alert panel drops from top `-100px` with a spring bounce.
    *   *Reduced:* Alert panel fades in `opacity: 0 -> 1` over 0.2s with zero spatial movement[cite: 2].

## Best Practices
*   **Staggered Reveals:** Use staggered timings (e.g., 0.05s offset) for lists or telemetry data points to create a "wave" effect, emphasizing the flow of data without overwhelming the user.
*   **Anticipation and Follow-through:** Use slight pull-backs before a rapid movement to add weight and realism to UI elements, simulating mechanical inertia.

## Anti-patterns
*   **The "Everything Moves" Problem:** Animating every single dial, chart, and text box simultaneously on scroll, causing motion sickness and obscuring the actual telemetry data[cite: 2].
*   **Floaty UI:** Using generic `sine.inOut` eases that make the high-stakes F1 dashboard feel like a serene meditation app.
*   **Ignoring the Z-Axis:** Forgetting to specify camera zooms or FOV shifts in the 3D R3F specification, leaving the WebGL canvas static while the DOM moves around it[cite: 2].

## Quality Checklist
*   [ ] Does the motion concept evoke Formula 1 physics (acceleration, precision)?[cite: 2]
*   [ ] Is the choreography restricted to GPU-accelerated properties (`transform`/`opacity`)?
*   [ ] Is there a defined alternative sequence for reduced-motion users?[cite: 2]

## Validation Checklist
*   [ ] Does the specification for Minute 3 (The Cognitive Firewall Save) clearly dictate how the UI locks the channel to prevent cognitive overload?[cite: 1]
*   [ ] Are the easing curves documented well enough for the GSAP Motion System to register them as `CustomEase` objects?[cite: 2]

## Examples

**Example Motion Specification (Markdown format for GSAP handoff):**

```markdown
### Sequence: Cognitive Firewall Activation
**Trigger:** Driver Cognitive Load > 85% AND entering critical braking zone.

**Intent:** Snap the engineer's attention to the lock. It should feel aggressive, mechanical, and absolute—like a physical firewall slamming shut.

**Easing Definition:**
*   `ease-f1-slam`: `CustomEase("slam", "M0,0 C0.1,0.9 0.2,1 1,1")` (Extremely fast initial velocity, abrupt stop).

**Choreography:**
1.  **Audio Stream Controller:**
    *   Action: Disable / Gray out.
    *   Motion: `opacity: 1 -> 0.4`
    *   Duration: `0.2s`, Ease: `linear`
2.  **Firewall Backdrop Overlay:**
    *   Action: Tint the screen red.
    *   Motion: `opacity: 0 -> 1`
    *   Duration: `0.1s`, Ease: `power1.in`
3.  **Firewall Alert Banner ("CHANNEL LOCKED"):**
    *   Action: Slam into center screen.
    *   Motion (Standard): `scale: 1.5 -> 1`, `opacity: 0 -> 1`
    *   Motion (Reduced): `opacity: 0 -> 1` (No scale)
    *   Duration: `0.3s`, Ease: `ease-f1-slam`
