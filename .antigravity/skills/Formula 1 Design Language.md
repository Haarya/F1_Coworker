# Antigravity Skill: Formula 1 Design Language

## Description
The Formula 1 Design Language skill is the authoritative guardian of the platform's visual thematic identity[cite: 2]. While the *UI/UX Design System* establishes the structural skeleton (grids, base spacing, semantic tokens), this skill provides the premium "skin." It is responsible for meticulously blending Apple-quality polish with high-octane motorsport aesthetics—specifically integrating carbon fiber, brushed metal, glassmorphism, and telemetry-inspired visual cues to ensure the AeroFlow dashboard feels like an authentic pit-wall command center.

## Activation Criteria
Activate this skill when:
*   Applying specific thematic styles to UI components (e.g., turning a standard line chart into a glowing, neon-accented `Telemetry & Stress Plotter`)[cite: 1].
*   Selecting and applying motorsport-inspired typography for data-heavy displays (e.g., monospaced fonts for the FastF1 live telemetry data)[cite: 1, 2].
*   Styling critical AeroFlow elements like the tachometer-style `Cognitive Load Gauge` or the flashing `Divergence Alert Banner`[cite: 1].
*   Implementing 2D UI textures such as carbon fiber backgrounds, brushed metal borders, or HUD (Heads-Up Display) panels[cite: 2].
*   Adding racing lines or technical crosshairs to the UI to improve clarity and reinforce the engineering theme[cite: 2].

## When NOT to Activate
Do NOT activate this skill when:
*   Defining the core spacing scale, breakpoints, or base accessibility tokens (delegate to **UI/UX Design System**)[cite: 2].
*   Structuring the React component tree or prop interfaces (delegate to **Component Architect**)[cite: 2].
*   Applying textures or materials to 3D models like the Track Map (delegate to **3D Asset Manager** and **Three.js & React Three Fiber**)[cite: 1, 2].
*   Choreographing the actual movement or acceleration animations of UI elements (delegate to **Motion Designer** and **GSAP Motion System**)[cite: 2].

## Responsibilities
*   **Thematic Execution:** Translate standard UI layouts into premium, motorsport-grade interfaces using advanced CSS (gradients, backdrops, shadows, clipping paths)[cite: 2].
*   **Typography Curation:** Enforce the use of specific typographic styles—monospaced fonts for numerical telemetry, aggressive/bold fonts for critical alerts, and clean sans-serifs for readability[cite: 2].
*   **Texture Management (2D UI):** Source, optimize, and apply CSS/SVG-based textures (carbon fiber weaves, glass overlays) that give depth to the pit-wall dashboard[cite: 1, 2].
*   **Visual Hierarchy via Aesthetics:** Use the design language to prioritize information, ensuring that critical data (like a Red stress gauge or a Cognitive Firewall lock) immediately captures the user's attention over background UI noise[cite: 1].

## Scope
*   Advanced CSS/Tailwind classes related strictly to theming (e.g., `backdrop-blur`, `bg-gradient-to-br`, custom `box-shadow` for HUD glows).
*   2D aesthetic assets (`.svg` racing lines, grid patterns, UI textures).
*   Font family assignments and text-shadow treatments for data legibility.

## Non-goals
*   Building generic button or card structures from scratch.
*   Dictating the animation timings of the `Divergence Alert Banner` (this skill designs what it looks like; the Motion Designer determines how it flashes)[cite: 1, 2].
*   Setting up the 3D scene lighting.

## Inputs
*   Structural primitives from the **UI/UX Design System**[cite: 2].
*   Layout architecture from the **Component Architect**[cite: 2].
*   AeroFlow functional requirements (e.g., Green/Yellow/Red states for the stress index)[cite: 1].

## Outputs
*   Thematic CSS classes, styled-components, or Tailwind variant configurations.
*   Curated SVG UI assets (crosshairs, HUD borders, corner brackets).
*   Implementation guidelines for applying the F1 aesthetic to charts and gauges.

## Dependencies
*   **UI/UX Design System:** Relies on the base semantic tokens (e.g., taking the `color-critical` token and applying a specific F1 neon-glow shadow to it)[cite: 2].

## Related Skills
*   **Component Architect (Consumer):** Applies the thematic classes generated by this skill to the React components.
*   **Three.js & React Three Fiber (Parallel):** Both skills aim to achieve a cohesive F1 aesthetic, but this skill focuses on the 2DOM/HTML layer while the 3D skill handles the WebGL layer[cite: 2].

## Folder Ownership
Governs thematic assets and style layers within:
*   `/src/assets/textures/` (Strictly for 2D UI textures like `carbon-fiber-tile.webp` or `brushed-metal-bg.png`. 3D materials belong to the 3D Asset Manager)[cite: 2].
*   `/src/styles/themes/` or specific Tailwind plugin files (e.g., `tailwind.f1-theme.js`).

## Naming Conventions
*   **Thematic Classes/Tokens:** Prefix highly specific stylistic overrides with `f1-` or `hud-` (e.g., `f1-panel-glass`, `hud-corner-bracket`, `f1-text-telemetry`).
*   **Texture Assets:** Use descriptive hyphenation (e.g., `bg-carbon-weave-dark.svg`).

## Coding Standards
*   **CSS over Images:** Whenever possible, generate carbon fiber, grid lines, or gradients using pure CSS (`linear-gradient`, `radial-gradient`, `repeating-linear-gradient`) rather than loading heavy image assets to maintain high performance[cite: 2].
*   **Tailwind Arbitrary Values:** Limit the use of arbitrary values (e.g., `bg-[#1a1a1a]`). Instead, map them to the F1-specific Tailwind config layer.
*   **Composability:** Thematic classes should be composable. A `f1-panel-glass` class should not hardcode the width or height of the component.

## Design Standards
*   **Premium Motorsport Aesthetics:** Use dark, deep grays (not pure black) as the primary background to mimic pit-wall monitors, accented by highly saturated, luminescent colors (neon green, warning yellow, critical red) for the data streams[cite: 1, 2].
*   **Telemetry Aesthetics:** Data plots and the `Live Teleprompter` should feel like raw engineering outputs. Use sharp corners, technical borders (like cropped corners or brackets), and monospaced typefaces[cite: 1, 2].
*   **Restraint:** Use racing lines, HUD panels, and timing-inspired graphics *only* when they improve clarity. Do not clutter the dashboard; motion and design should reinforce the high-stakes data, not distract from it[cite: 1, 2].

## Performance Standards
*   **Backdrop Filter Budgets:** `backdrop-filter: blur()` (Glassmorphism) is GPU-intensive. Apply it selectively (e.g., only on the floating `Cognitive Firewall Overlay`) rather than on every nested card to maintain 60 FPS during high-frequency telemetry updates[cite: 1, 2].
*   **Vector Graphics:** All UI overlays (crosshairs, racing lines) must be optimized SVGs, not PNGs.

## Accessibility Considerations
*   **Contrast on Textures:** Ensure that text placed over carbon fiber patterns or glassmorphic backgrounds maintains a 4.5:1 WCAG contrast ratio[cite: 2]. Apply subtle solid background overlays beneath text if the texture causes readability issues.
*   **Color as Information:** The `Cognitive Load Gauge` cannot rely *only* on color (Green/Yellow/Red) to convey stress. The design language must incorporate positional, typographic, or iconographic indicators to support colorblind users[cite: 1, 2].

## Best Practices
*   **Layering:** Build the aesthetic in layers. Start with a solid dark surface (UI/UX token), add a subtle CSS noise/carbon texture (F1 Design Language), apply a glassmorphic border, and top with high-contrast text.
*   **Consistent Glows:** Standardize CSS `box-shadow` or `drop-shadow` values to simulate LED screen glows on critical data points (like the Divergence Alert).

## Anti-patterns
*   **Over-Styling:** Adding flame graphics, checkered flags, or overly literal racing metaphors that break the "premium Apple-quality polish" and "engineering excellence" mandate[cite: 2].
*   **Illegible Data:** Using stylized, overly aggressive racing fonts for the actual telemetry numbers, making the 150,000 data points hard to read[cite: 1, 2].
*   **Heavy Assets:** Using a 5MB PNG for a carbon fiber background instead of a 2KB repeating SVG pattern or CSS gradient.

## Quality Checklist
*   [ ] Does the aesthetic feel like a premium, high-stakes engineering tool?
*   [ ] Are telemetry numbers styled using a readable, monospaced font?
*   [ ] Are textures generated via CSS/SVG where possible to minimize asset load?
*   [ ] Do the thematic elements avoid distracting from the core AeroFlow data?[cite: 1, 2]

## Validation Checklist
*   [ ] Does the `Cognitive Firewall Overlay` visually command the absolute highest hierarchy on the screen when activated?[cite: 1]
*   [ ] Is the `Cognitive Load Gauge` visually distinct from standard UI elements, utilizing tachometer-inspired styling?[cite: 1]
*   [ ] Has the design language been applied without breaking the underlying responsive grid defined by the UI/UX skill?[cite: 2]

## Examples

```css
/* src/styles/f1-theme.css */
@layer components {
  /* Premium Glassmorphic HUD Panel */
  .f1-panel-glass {
    @apply bg-surface-base/80 backdrop-blur-md border border-white/10 shadow-lg relative overflow-hidden;
  }

  /* Simulated Carbon Fiber Weave (Pure CSS for Performance) */
  .f1-bg-carbon {
    background-color: #121212;
    background-image: 
      linear-gradient(45deg, #000 25%, transparent 25%, transparent 75%, #000 75%, #000), 
      linear-gradient(45deg, #000 25%, transparent 25%, transparent 75%, #000 75%, #000);
    background-size: 8px 8px;
    background-position: 0 0, 4px 4px;
    opacity: 0.9;
  }

  /* Telemetry Glow for Critical Alerts */
  .f1-glow-critical {
    @apply text-status-critical;
    text-shadow: 0 0 8px theme('colors.status.critical / 60%');
  }
}
