# Antigravity Skill: UI/UX Design System

## Description
The UI/UX Design System skill establishes the structural visual foundation of the application[cite: 2]. It defines the "skeleton" of the user interface—typography scales, spacing increments, grid systems, base interactive primitives (buttons, inputs, cards), and overall consistency rules[cite: 2]. While the *Formula 1 Design Language* skill dictates the thematic "skin" (e.g., carbon fiber textures, motorsport styling), this skill guarantees that the underlying CSS architecture is scalable, consistent, and adheres to Apple-quality structural polish[cite: 2]. 

## Activation Criteria
Activate this skill when:
*   Defining or updating global design tokens (CSS variables or `tailwind.config.js`).
*   Establishing standardized spacing, grid, and layout utility systems.
*   Building core, reusable UI primitives (e.g., `Button`, `Card`, `TextInput`) that act as building blocks for larger components[cite: 2].
*   Configuring typography scales and standard font-weight variants.
*   Standardizing focus states, hover transitions, and interactive feedback mechanisms.

## When NOT to Activate
Do NOT activate this skill when:
*   Applying specific motorsport thematic elements, carbon fiber aesthetics, or HUD-specific styling (delegate to **Formula 1 Design Language**)[cite: 2].
*   Designing complex component logic, state handling, or prop interfaces (delegate to **Component Architect**)[cite: 2].
*   Writing GSAP animation sequences or ScrollTriggers (delegate to **GSAP Motion System**)[cite: 2].
*   Auditing semantic HTML or ARIA live regions for the telemetry streams (delegate to **Accessibility**)[cite: 2].

## Responsibilities
*   **Design Tokens:** Maintain a strict, centralized repository of design tokens (colors, spacing, typography, z-index, radii).
*   **Core Primitives:** Develop the lowest-level UI components (`/src/components/UI/`) that are purely presentational and devoid of business logic[cite: 2].
*   **Consistency Enforcement:** Ensure all UI elements align to a defined grid (e.g., an 8pt system) and utilize standard typography scales to prevent visual fragmentation.
*   **Interactive Baselines:** Standardize accessible focus rings, active states, and disabled states across all interactive elements.

## Scope
*   Global CSS configuration and utility class generation (e.g., Tailwind configuration)[cite: 2].
*   Base UI component library (`Button`, `Badge`, `Card`, `Tooltip`).
*   Responsive breakpoints and fluid typography rules[cite: 2].
*   Structural form elements.

## Non-goals
*   Choreographing motion design (this system defines the *duration* tokens for CSS transitions, but not the GSAP choreography)[cite: 2].
*   Managing complex layout compositions of the high-stakes pit-wall command center (this is the Component Architect's domain)[cite: 1, 2].
*   Defining specific 3D materials or canvas layers[cite: 2].

## Inputs
*   Component architectural boundaries defined by the **Component Architect**[cite: 2].
*   Thematic rules provided by the **Formula 1 Design Language** skill[cite: 2].
*   Standard Figma design system files or style guides.

## Outputs
*   A configured `tailwind.config.ts` (or global `variables.css` file) populated with semantic design tokens.
*   Reusable, prop-driven structural UI components within `src/components/UI/`[cite: 2].
*   Global style entry points (e.g., `index.css`).

## Dependencies
*   **React + Vite:** Relies on the build toolchain to process CSS/PostCSS/Tailwind[cite: 2].

## Related Skills
*   **Formula 1 Design Language (Symbiotic):** The UI/UX Design System provides the variables (e.g., `color-accent-red`); the Formula 1 Design Language dictates *where* and *how* that red is applied to mimic F1 telemetry aesthetics[cite: 1, 2].
*   **Component Architect (Consumer):** Consumes the base primitives generated by this skill to construct complex dashboard panels[cite: 1, 2].
*   **Accessibility (Auditor):** Verifies that the base color contrasts and focus states defined here meet WCAG standards[cite: 2].

## Folder Ownership
Governs the foundational style layers and primitive components within:
*   Root styling configuration: `tailwind.config.js`, `postcss.config.js`, or equivalent.
*   Global stylesheets: `/src/styles/` or the root `index.css`.
*   Primitive UI components: `/src/components/UI/` (shared boundary with Component Architect; this skill owns the generic building blocks like `BaseButton`, `Container`)[cite: 2].

## Naming Conventions
*   **Design Tokens:** Semantic naming over literal naming (e.g., `color-primary`, `color-critical`, `spacing-md`, `text-body-lg`).
*   **Base Components:** Prefix with `Base` or keep strictly generic (e.g., `Button`, `IconButton`, `Grid`).
*   **CSS Variables:** Follow standard `--prefix-property-variant` (e.g., `--af-color-surface-elevated`).

## Coding Standards
*   **Token-First Styling:** Never use magic numbers or hardcoded hex codes. All styling MUST reference a configured design token.
*   **Utility-First Modularity:** Prefer atomic utility classes (like Tailwind) to prevent cascading CSS side-effects, ensuring components remain structurally isolated.
*   **Polymorphic Primitives:** Design base components like `Text` or `Button` to accept an `as` prop (e.g., `<Text as="h1">`) to maintain semantic HTML while enforcing the design scale.

## Design Standards
*   **8-Point Grid System:** All padding, margins, and layout dimensions must adhere to multiples of 8 (or 4 for micro-adjustments).
*   **Predictable Scaling:** Typography should use a calculated modular scale (e.g., Major Third or Perfect Fourth) to ensure a consistent rhythm between headers and body copy.
*   **Z-Index Management:** Define a strict Z-index scale (e.g., `z-base`, `z-dropdown`, `z-modal`, `z-firewall-overlay`) to prevent stacking context wars, particularly for the Cognitive Firewall Overlay[cite: 1].

## Performance Standards
*   **CSS Optimization:** Purge unused CSS styles in production builds. If using Tailwind, rely on its JIT compiler to keep the stylesheet footprint minimal[cite: 2].
*   **Avoid Expensive CSS:** Limit the use of CSS properties that trigger layout thrashing or heavy repaints (e.g., animating `box-shadow` or `width`). Prefer `transform` and `opacity` for micro-interactions.

## Accessibility Considerations
*   **Contrast Ratios:** All text and critical UI elements (especially the telemetry data plots) must mathematically pass WCAG AA (4.5:1) minimum contrast against their backgrounds[cite: 2].
*   **Focus Visibility:** Implement robust, non-clipping `:focus-visible` states for keyboard navigation[cite: 2].
*   **Relative Units:** Use `rem` for typography and spacing to respect the user's browser-level text size preferences.

## Best Practices
*   **Separation of State and Style:** UI primitives should accept standard DOM attributes and generic boolean props (`isDisabled`, `isActive`), leaving the business logic mapping to the Component Architect.
*   **Extensible Variants:** Use a variant management library (like `cva` - class variance authority) to handle complex, multi-state styling for UI primitives elegantly.

## Anti-patterns
*   **Magic Numbers:** Using `margin-top: 17px` or `#FF0000` directly in a component file.
*   **Overriding with `!important`:** Forcing styles via `!important`, indicating a failure in the CSS architecture or specificity hierarchy.
*   **Overly Specific Naming:** Naming a token `--button-red-background` instead of `--color-critical-action`.

## Quality Checklist
*   [ ] Are all layout properties tied to a standardized grid scale?
*   [ ] Do all interactive elements have defined `:hover`, `:active`, `:disabled`, and `:focus-visible` states?
*   [ ] Are design tokens centralized and universally accessible to the component tree?

## Validation Checklist
*   [ ] Does the UI system provide the structural foundation required for the F1-inspired aesthetics without hardcoding thematic logic?[cite: 2]
*   [ ] Can the color and spacing systems easily support the visual states of the Cognitive Load Gauge (Green/Yellow/Red) and the flashing Divergence Alert Banner?[cite: 1]

## Examples

```typescript
// tailwind.config.ts (Design Token Configuration)
export default {
  theme: {
    extend: {
      colors: {
        // Semantic token names
        surface: {
          base: 'var(--color-surface-base)',
          elevated: 'var(--color-surface-elevated)',
        },
        status: {
          optimal: 'var(--color-status-green)', // Low stress
          warning: 'var(--color-status-yellow)', // Elevated stress
          critical: 'var(--color-status-red)', // > 85% Cognitive Load
        }
      },
      spacing: {
        'micro': '0.25rem', // 4px
        'sm': '0.5rem',     // 8px
        'md': '1rem',       // 16px
        'lg': '2rem',       // 32px
      },
      zIndex: {
        'base': '1',
        'telemetry': '10',
        'firewall': '9999', // Automated Strategic Radio Queuing overlay
      }
    }
  }
}
